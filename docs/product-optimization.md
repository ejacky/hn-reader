# HN Reader 产品优化方案：降低安装门槛

> 目标：把新用户从"安装扩展"到"完成首次摘要"的激活率从当前不足 10% 提升至 40% 以上，并为后续商业化奠定基础。

---

## 1. 背景

HN Reader 当前采用 **浏览器扩展 + 本地 Go 服务** 的架构。虽然本地优先保障了隐私，但安装路径过长、配置复杂，严重制约了用户增长。

### 1.1 当前安装漏斗

```
发现扩展
  → 安装扩展
  → 发现需要下载服务端
  → 下载 exe / 配置环境
  → 管理员权限安装
  → 输入 LLM API Key
  → 服务启动成功
  → 扩展检测到 localhost:8080
  → 打开 HN 页面使用
```

### 1.2 主要卡点

| 卡点 | 影响 |
|---|---|
| 安装扩展后才发现要配本地服务 | 预期落差大，直接流失 |
| Windows 安装包 + 管理员权限 | 非管理员、Mac/Linux、公司电脑用户无法使用 |
| 需要自备 LLM API Key | 普通用户没有 Key，或担心费用 |
| 无首次使用引导 | 用户不知道 `[summary]` 和高亮含义 |
| 服务连接失败无友好降级 | 挫败感强，容易卸载 |

---

## 2. 优化方向

采用 **"云服务优先，本地服务保留"** 的双轨策略：

- **默认路径**：云服务，即装即用，降低 80% 用户的激活门槛。
- **高级路径**：本地服务，保留给隐私敏感用户，作为免费替代方案。
- **全程引导**：从安装到第一次使用，提供清晰的 Onboarding。

---

## 3. 云服务方案

### 3.1 架构

```
Chrome Extension
       ↓ HTTPS
HN Reader Cloud API（官方托管）
       ↓
   LLM API
```

扩展首次打开时提供两种模式选择：

- **☁️ 使用 HN Reader 云服务** — 输入 token / 登录即可使用
- **🖥️ 使用本地服务** — 保留现有流程，但优化配置体验

### 3.2 功能范围

| 功能 | 云服务 | 本地服务 |
|---|---|---|
| 文章摘要 | ✅ | ✅ |
| 评论摘要 | ✅ | ✅ |
| 兴趣画像 | ✅ | ✅ |
| 列表页匹配高亮 | ✅ | ✅ |
| 跨设备同步 | ✅ | ❌ |
| 阅读趋势报告 | ✅ Pro | ❌ |
| 端到端加密 | 可选 | 默认 |

### 3.3 定价（Freemium）

| 层级 | 价格 | 摘要额度 | 推荐 |
|---|---|---|---|
| Free | 免费 | 50 次/月 | 基础匹配 |
| Pro | $5/月 或 $39/年 | 500 次/月 | 语义匹配 + 趋势报告 |
| Unlimited | $12/月 | 无限 | 全部功能 |

> 本地模式始终免费，作为价格敏感用户的备选方案。

## 4. 新手引导设计

### 4.1 扩展内首次引导（3 步）

**Step 1：欢迎 + 模式选择**

```
欢迎使用 HN Reader

HN Reader 是你的 AI 阅读助手，帮你快速判断 HN 上哪些文章值得读。

[☁️ 免费开始使用（推荐）]    [🖥️ 使用本地服务]
```

**Step 2：偏好设置**

- 选择摘要语言：中文 / English
- 云模式下简要说明隐私策略

**Step 3：完成 + 跳转**

```
已就绪！

去 Hacker News 试试吧，点击文章旁的 [summary] 查看 AI 摘要。

[打开 Hacker News]
```

### 4.2 本地服务配置向导

针对选择本地服务的用户：

1. 扩展自动检测 `localhost:8080`
2. 若未启动，显示对应平台下载选项：
   - Windows：下载安装包
   - macOS/Linux：Docker 命令或二进制
3. 在 popup 内输入 LLM API Key，扩展自动写入服务端配置
4. 自动 health check，成功后进入使用引导

### 4.3 HN 页面内首次引导

用户第一次访问 `news.ycombinator.com` 时，显示非侵入式浮层：

```
┌─────────────────────────────────────────┐
│  👋 HN Reader 已就绪                      │
│                                         │
│  • 点击 [summary] 查看 AI 摘要            │
│  • 橙色边框 = 可能感兴趣的文章              │
│  • 点击扩展图标查看推荐和数据              │
│                                         │
│  [知道了，不再显示]                        │
└─────────────────────────────────────────┘
```

### 4.4 空状态优化

| 位置 | 当前 | 优化后 |
|---|---|---|
| Recommendations | 隐藏 | "我们还在了解你的偏好，多点击几篇感兴趣的文章" |
| Stats | 隐藏 | 显示信号收集进度和下一步提示 |

## 5. 隐私策略

引入云服务后，必须明确区分两种模式的数据边界：

| 数据 | 云服务 | 本地服务 |
|---|---|---|
| 摘要缓存 | 服务端存储 | 本地 SQLite |
| 阅读信号 | 服务端存储 | 本地 SQLite |
| 兴趣标签 | 服务端存储 | 本地 SQLite |
| 原始网页全文 | 不存储（仅用于生成摘要） | 本地可选 |
| 浏览历史 | 不收集 | 不收集 |

**用户控制**：

- 设置页显示当前模式
- 提供"导出我的数据"（JSON）
- 提供"删除所有云端数据"
- 云模式下明确告知数据流向，承诺不出售、不用于模型训练

## 6. 实施路线图

### Phase 1：云服务 MVP（4-6 周）

**后端**

- 新建官方云服务后端，复用现有 `summarizer`、`storage`、`model` 逻辑
- 用户认证：支持匿名设备 ID 或邮箱登录
- 新增云 API：摘要、信号、推荐、配额
- 计费/配额系统

**扩展**

- popup 增加模式选择页
- `background.js` 根据 mode 路由到不同服务端点
- 保存用户模式偏好到 `chrome.storage.local`

**运维**

- 部署到 Fly.io / Vercel / AWS
- 监控 LLM 成本和异常调用

### Phase 2：新手引导（2-3 周）

- 扩展内 welcome 页面
- 首次使用状态机
- HN 页面内引导浮层
- 空状态优化

### Phase 3：商业化（2 周）

- 配额展示和限额提示
- 达到额度时的升级引导
- 付费订阅接入（Stripe / LemonSqueezy）

## 7. 关键指标

### 北极星指标

**7 日激活率**：安装扩展后 7 天内完成首次摘要的用户比例

目标：从当前 <10% 提升至 **40%**

### 过程指标

| 指标 | 当前 | 目标 |
|---|---|---|
| 安装 → 服务可用 | ~30% | 80% |
| 服务可用 → 完成首次摘要 | ~60% | 70% |
| 首次摘要 → 7 日内再次使用 | 待统计 | 50% |
| 免费 → 付费转化率 | 0% | 5% |
| 云服务 → 本地切换率 | - | <15% |

### 埋点事件

- `install`、`onboarding_start`、`onboarding_complete`
- `mode_selected`（cloud / local）
- `service_connected`、`service_connect_failed`
- `summary_clicked`、`summary_loaded`
- `recommendation_clicked`
- `upgrade_prompt_shown`、`upgrade_clicked`

## 8. MVP 最小改动清单

如果资源有限，优先完成以下 5 项，即可显著降低门槛：

1. **popup 增加云服务 / 本地服务选择页**
2. **提供官方云服务匿名试用（50 次/月，无需登录）**
3. **扩展内直接配置本地服务的 API Key**（替代手动编辑 `.env`）
4. **首次安装后显示 3 步引导**
5. **HN 页面首次访问时显示 `[summary]` 和高亮的解释浮层**

预计工期：**6-8 周**

预计效果：新用户激活率提升 **2-3 倍**，并为后续商业化验证付费意愿。

---

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 老用户反对云服务 | 本地模式保留；隐私政策透明；核心代码开源 |
| LLM 成本失控 | 配额限制、摘要缓存、使用低成本模型、异常监控 |
| 云服务被滥用 | Rate limit、登录要求、调用行为检测 |
| 推荐质量差影响转化 | 先 Free 验证点击率，再开放付费 |
| 跨平台支持不足 | 云服务天然跨平台；本地模式逐步支持 macOS/Linux |

---

## 10. 总结

降低安装门槛的核心不是放弃本地隐私，而是**给用户选择权**：

- 想要即装即用的用户 → 云服务
- 想要完全掌控数据的用户 → 本地服务

配合清晰的新手引导和合理的 Freemium 定价，可以在不背叛核心用户信任的前提下，把 HN Reader 从极客工具扩展为更广泛技术从业者使用的阅读助手。
